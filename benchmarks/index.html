benchmarks

Benchmarks

One core per server, loopback, medians of five interleaved rounds on a 4-vCPU virtual machine; the thin line under a bar runs from the lowest round to the highest. giong is not faster than everything at everything: the charts say where the design pays off and where it does not.

Full tables and raw output: README · bench/results/

method

How each number is measured

The server gets one core and the load generator another, so they never compete. Servers take turns in interleaved rounds, so a change in the machine's speed hits all of them alike. A bar is the median of five rounds; the thin line under it runs from the lowest round to the highest.

bench/run.sh →

What these numbers do not show

  • One machine. Everything is loopback inside a 4-vCPU virtual machine, where the load generator competes for the same few cores. The 14-core run in the README (1 to 10 workers, peak 1.50M requests/s) is loopback too, on a desktop under WSL2.
  • Not measured: a physical network, scaling on bare metal, and disks. The file benchmark reads cached data only.
  • 8 KB responses: giong and Monoio serve 63–64k requests/s, everything else 35–37k. Most of that gap comes from the virtual machine. On physical hardware expect a smaller one.
  • /compute is the same for everyone, as it should be: the time goes into the function, not the runtime.
  • Two cores are measured and are not a ranking. Two wrk threads are as likely to be the limit as the server.
  • Monoio is compared tuned, with DEFER_TASKRUN passed in. Its default ring is about 20% slower on the small response; comparing against that would flatter giong.

Run them yourself

Each script builds the servers, runs the load generator and writes its summary to bench/results/. Run them on a quiet Linux machine; they take minutes, not seconds.
