giong

Runtime

guide · docs.rs · crates.io · source

cargo add giong

The runtime: TCP, UDP, Unix sockets, files, timers, DNS, channels and graceful shutdown.

  • Builder::new().workers(n), one worker per core
  • TcpListener, TcpStream, UdpSocket, UnixListener, UnixStream
  • fs::File with read_at and write_at, fs::read, read_dir, rename
  • net::lookup_host without blocking; sync::mpsc, bounded, oneshot
  • spawn_on, spawn_balanced and bind_balanced to spread new work
  • 8×against tokio::fs · File reads, 4 KiB at an offset

about 40,700 lines · 288 tests · 3 dependencies at most on any system: socket2, plus libc and io-uring on Linux, libc on macOS, windows-sys on Windows

giong-proto

Protocols

guide · docs.rs · crates.io · source

cargo add giong-proto

Protocol Buffers decoded as views over the receive buffer. Strings, bytes, repeated fields and maps borrow from the input; encoding writes message structs whose fields borrow too.

  • OrderView::decode(&buf)?: a view that reads fields as it is asked
  • Message structs and Encode for writing
  • Code generated by giong-grpc-build, no protoc to install
  • Coded errors GIONG-E4001 to GIONG-E4008

about 2,100 lines · 9 tests · passes Google's protobuf conformance suite; fuzzed against prost

giong-grpc-build

Tooling

guide · docs.rs · crates.io · source

cargo add giong-grpc-build

Generates giong-proto messages and, for each service, a trait, a server and a client from .proto files in build.rs. Parsed in Rust: no protoc to install.

  • giong_grpc_build::compile(&["proto/shop.proto"], &["proto"])
  • The generated file carries the descriptors server reflection serves

about 1,900 lines · 4 tests · no protoc binary needed

giong-quic

Protocols

guide · docs.rs · crates.io · source

cargo add giong-quic

QUIC (RFC 9000) on giong's UDP sockets, one endpoint per worker, with TLS 1.3 from rustls. It carries giong-http's HTTP/3 server and client.

  • Connection IDs name their worker, so a datagram that reaches another worker is passed on
  • Bidirectional and unidirectional streams, reset and stop with a code
  • 0-RTT for servers that opt in; Retry under load; stateless resets
  • GSO, GRO and ECN on Linux through giong's UDP offloads
  • Coded errors GIONG-E3601 to GIONG-E3605

about 4,000 lines · 51 tests · h3spec: 85 of 86 cases pass, 0 fail (one needs 0-RTT, off in the example)

giong-tls

Protocols

guide · docs.rs · crates.io · source

cargo add giong-tls

TLS 1.2 and 1.3 for servers and clients on rustls with ring. No OpenSSL.

  • TlsAcceptor::with_certificates(&certs); TlsConnector with the system's or built-in roots
  • recv() is cancel safe
  • A cancelled write poisons the sending side instead of corrupting the record stream
  • ALPN, client certificates and a handshake timeout
  • Kernel TLS after the handshake (Ktls::Auto), and files sent with sendfile
  • 1.8×against Axum + rustls · HTTPS, kept-alive

about 5,900 lines · 76 tests · TLS costs 2% on /json (main, after 0.8.0)

giong-http

Protocols

guide · docs.rs · crates.io · source

cargo add giong-http

A small, strict HTTP/1.1 and HTTP/2 server with one async handler, and a client that speaks both.

  • HTTP/2 through ALPN or with prior knowledge, for the same handlers
  • Keep-alive, pipelining, bodies by Content-Length or chunked, streamed both ways
  • Limits and timeouts everywhere; HTTP/2 rapid reset and floods answered with a GOAWAY, and what a connection holds bounded by a budget
  • Answers 400 to any request a proxy in front could read differently
  • Server::serve, serve_unix, serve_tls; a pooled HTTPS Client with proxies and gzip behind client
  • 1.8×against Axum + rustls · HTTPS, kept-alive
  • 10× lessagainst Axum · Memory per idle connection

about 31,800 lines · 215 tests · h2spec: all 147 cases pass

giong-grpc

Protocols

guide · docs.rs · crates.io · source

cargo add giong-grpc

gRPC servers and clients on giong-http's HTTP/2. Messages are read as giong-proto views without copies.

  • The four kinds of call: unary, server streaming, client streaming, bidirectional
  • Deadlines, cancellation, metadata, statuses with details, gzip per message
  • giong_grpc::Server is a giong-http handler; a Channel shares connections
  • Health checking and server reflection (grpcurl works without .proto files)
  • Interoperates with grpc-go in both directions, on io_uring and epoll, in CI
  • 1.5×against tonic · gRPC, 100-byte unary calls

about 9,300 lines · 65 tests · up to 1.5× tonic's 100-byte unary calls on one server thread

giong-postgres

Clients

guide · docs.rs · crates.io · source

cargo add giong-postgres

A PostgreSQL client and pool. The statements of every task pipeline over a few connections.

  • Client::connect, query, execute, transaction, cancel_token
  • A Pool per worker: shared, pipelined statements; get() for a transaction
  • Every statement prepared once per connection and cached
  • TLS verified by default for remote hosts; SCRAM-SHA-256; require_auth
  • A connection taken with get() comes back to the pool with its session reset
  • 3.3×against tokio-postgres + deadpool · PostgreSQL, one row by key

about 8,900 lines · 107 tests · 3.3× deadpool's statements per core (main, after 0.8.0)

giong-web

Framework

guide · docs.rs · crates.io · source

cargo add giong-web

A router, middleware and JSON on giong-http. Handlers are plain async fns; every error is a coded problem+json answer.

  • Router::new().get("/users/{id}", user).nest("/api", api).build(state)
  • req.param::<u64>("id")?, req.query::<T>()?, req.json::<T>()?
  • RequestId, Logger (JSON lines), Cors, Compression (gzip), Timeout
  • 404, 405 with Allow, OPTIONS and HEAD answered for you; App::handle tests without a socket
  • 1.3×against axum · Routing and JSON

about 7,900 lines · 110 tests · 1.3× axum's /json on one core

giong-mcp

Tooling

guide · docs.rs · crates.io · source

cargo add giong-mcp

A read-only MCP server that lets an AI agent look inside a running service: which task blocks a worker, which line spawned the tasks that leak, how full the pools are.

  • let _mcp = giong_mcp::start_from_env(&handle);, on when GIONG_MCP is set
  • Tools: overview, workers, tasks, sources, profile
  • A worker stuck in one poll is reported with the line that spawned the task
  • Loopback or a Unix socket only; Host and Origin checked; a token required on TCP

about 4,200 lines · 34 tests · about 9 instructions per task poll

giong-compat

Protocols

guide · docs.rs · crates.io · source

cargo add giong-compat

AsyncRead, AsyncWrite and AsyncBufRead from Tokio and futures-io for giong's streams, so protocol crates that take a stream run on giong with no Tokio runtime.

  • Compat::new(stream) for TcpStream, UnixStream and TlsStream
  • Tested with tokio-rustls, futures-rustls, tokio-tungstenite, h2, hyper's conn and tokio-util's codecs
  • Buffered writes like BufWriter; reads lose nothing when cancelled
  • Says plainly which crates cannot work: those that need Tokio's reactor, timers or spawn

about 1,100 lines · 42 tests · one copy per byte; sending costs up to 20% of throughput

cargo add giong-cli

The giong command: a project that passes its tests from the first minute, a dev runner that swaps builds without refusing a request, checks and fixes in JSON, and an MCP server.

  • giong new, giong dev --background, giong check --json, giong test
  • Restarts on save: 0 failed requests out of 102,061 over 100 restarts under load

  • Loopback only, a token for the dashboard, secrets kept out of recordings, MCP read-only

about 37,400 lines · 391 tests · 0 failed requests over 100 restarts
